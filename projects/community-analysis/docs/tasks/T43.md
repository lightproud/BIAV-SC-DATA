# T43 生命周期与推送

```text
【工单 T43】生命周期与推送
阶段：4　依赖：T40
目标：每个议题的状态由计数算出；只在三种变化时打扰人。
说明：规则全部在配置里，是起点值；回测后由人调整。
产出：
- `src/yuqing/issues/lifecycle.py`
- `tests/t43_lifecycle_test.py`
规则：
1. 每日按议题 × 社区圈聚合反馈点数与独立发言人数。
2. 萌芽：首次出现后 `emerging_hours` 内，或累计独立发言人不足 `min_authors`。
3. 活跃：不在萌芽，且近 7 天日均独立发言人不低于该议题峰值（历史最高的 7 日均值）的 `cooling_ratio`。
4. 消退：近 7 天日均低于峰值的 `cooling_ratio`，但 `dormant_days` 内仍有新反馈点。
5. 沉寂：连续 `dormant_days` 没有新反馈点。复发：从沉寂回到活跃，复发次数加一。
6. “已回应”是标记：有关联裁定即为真，不改变状态。
7. 只在三种变化时推钉钉：进入活跃；出现在新的社区圈（该圈独立发言人首次达到 5）；复发。同一变化只推一次。
8. 哨兵议题（`config/sentinels.toml`）每次都列出，没有新反馈点时写“无信号”。
验收（全部通过才算完成）：
- `pytest -q tests/t43_lifecycle_test.py`：合成序列下的状态表；同一变化不重复推；哨兵的“无信号”行
完成后：提交、勾掉清单，接着做本阶段的下一张；阶段做完或遇到闸门再停。
```
