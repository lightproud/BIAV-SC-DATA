# T01 数据普查

```text
【工单 T01】数据普查
阶段：0　依赖：T00
目标：不花模型费，把数据湖的真实形状量出来，替换方案里的全部假设。
产出：
- `src/yuqing/lake/`、`src/yuqing/census/`
- `tests/fixtures/lake_mini/`、`tests/t01_census_test.py`
- 运行产出：`DATA_ROOT/reports/census/<日期>/census.json` 与 `census.html`
规则：
1. 先发现再统计：遍历 `LAKE_ROOT`，列出平台、目录层级、文件格式；每个平台抽样 1,000 条，报告字段名、类型、非空率。数据仓若已有统一读取接口，优先复用，并在报告里写明。
2. 已见过的一种布局（Discord，仅作线索，以发现结果为准）：`…/discord/{服务器}/channels/{频道号}/{YYYY-MM-DD}.jsonl`，每行一条，字段含 `timestamp`、`author_name`、`content`。
3. 统计项：按平台 × 月的条数；文本长度分位数与粗估 token（汉字、假名、谚文按 1，其余每 4 个字符按 1）；独立作者数；空消息、纯表情、有附件无文字的占比；完全重复率，分“同作者重复”和“不同作者的相同短句”两类；按文字脚本粗分语言；聊天类每个频道相邻消息间隔的 P50、P90、P99 与日均条数。
4. 专项：有没有“回复指向”“机器人标记”“平台原生消息 ID”“附件”这四类字段，覆盖率各多少。
5. 报告里放一张“方案假设与实测”对照表：原文总条数、聊天类占比、清洗后留存率、按默认参数试切得到的平均段长与单元总数。
6. 流式读取，不把整个平台读进内存。
7. 报告与终端输出只含统计与字段名，不含原文与作者名。
验收（全部通过才算完成）：
- `pytest -q tests/t01_census_test.py`：小样本上的结果与 `tests/expected/census.json` 完全一致
- `yuqing census --lake tests/fixtures/lake_mini --out /tmp/census` 生成 json 与 html
- 对真实 `LAKE_ROOT` 跑通并产出报告（报告不进版本库）
不要做：
- 不调模型；不写 `LAKE_ROOT`；小样本里不放真实玩家原文。
之后的人工闸门 G0（看普查报告）：你看 census.html：回复指向、机器人标记这些字段有没有；体量与假设差多少；消息间隔怎么分布。据此定切段参数，把漏斗和成本的数字换成实数。 这一步由人做，不要替人做。
完成后：提交、勾掉清单，接着做本阶段的下一张；阶段做完或遇到闸门再停。
```
