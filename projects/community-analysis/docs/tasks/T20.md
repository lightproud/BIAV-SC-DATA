# T20 模型网关适配器

```text
【工单 T20】模型网关适配器
阶段：2　依赖：T00
目标：全系统只有这一处调用模型；换模型、换网关只改配置。
说明：不依赖真实数据，可与第 1 阶段并行。
产出：
- `src/yuqing/llm/`
- `tests/t20_llm_test.py`
- 表 `runs`
规则：
1. 接口：`complete(system, user, model, json_schema=None)` 返回文本与用量。默认按 OpenAI 兼容的 chat completions 协议，另备 Anthropic Messages 协议的实现，按配置选用；再有不同就在这里加实现，不动上层。
2. 地址、密钥、模型名全部来自环境变量。
3. 超时；对 429 与 5xx 做带抖动的指数退避重试；并发上限与每分钟请求上限可配。
4. 每次调用记到 `runs`：模型、输入输出 token（网关不返回就估算并标明）、耗时、是否重试。不记密钥；默认不记正文，只记输入的哈希。
5. 预算：`budget.*` 未设置时拒绝调用真模型；到额即停并写收尾报告。
6. FakeLLM：按输入哈希返回预置输出，测试一律用它。
7. 提示词的固定部分（规则、词表、示例）放最前且逐字节稳定，变化部分放最后，便于网关缓存。
验收（全部通过才算完成）：
- `pytest -q tests/t20_llm_test.py`：重试、超时、记账、预算到额即停、FakeLLM 的确定性
- 人工：`yuqing llm ping --model $MODEL_LOW` 连真网关（不进自动测试）
完成后：提交、勾掉清单，接着做本阶段的下一张；阶段做完或遇到闸门再停。
```
