# T12 切段

```text
【工单 T12】切段
阶段：1　依赖：T11
目标：把聊天切成给模型读的阅读单元；评论和帖子一条一个单元。
产出：
- `src/yuqing/unitize/`
- `tests/t12_unitize_test.py`
- 表 `units`
规则：
1. 聊天类：同一频道按时间排序；相邻两条间隔超过 `gap_minutes`，或正文已满 `max_msgs`，就开新段。只收 `drop_reason` 为空的消息。
2. 只读上下文：每段开头附上同频道前一段最后 `overlap_msgs` 条，放进 `ctx_msg_ids`；被回复的那条若不在本段正文里且字段存在，也放进去。上下文不算正文，不参与抽取和作者计数。
3. 封口：增量运行时，最后一条消息距当前不足 `seal_minutes` 的段先不输出，留到下一轮。回放历史时全部封口。
4. 评论、帖子、评价：一条一个单元；有父帖或被回复内容时，把标题或文本（截到 200 字）放进 `ctx_text`。
5. `unit_ver` = 切段参数与规则版本的哈希；`unit_id` = 哈希(`unit_ver` + 首条 `msg_id`)。同参数重跑编号不变；参数一改就是新的 `unit_ver`，旧的保留。
6. 跨日的段归到首条消息那一天。
验收（全部通过才算完成）：
- `pytest -q tests/t12_unitize_test.py`：间隔规则、条数上限、重叠、回复拉入、封口各有样例
- 性质测试：每条未丢弃的聊天消息恰好属于一个单元的正文
- 同参数重跑编号稳定；改参数产生新 `unit_ver` 且旧分区不动
完成后：提交、勾掉清单，接着做本阶段的下一张；阶段做完或遇到闸门再停。
```
