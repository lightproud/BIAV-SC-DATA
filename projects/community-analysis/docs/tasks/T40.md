# T40 议题存储

```text
【工单 T40】议题存储
阶段：4　依赖：T22
目标：议题有持久编号，合并拆分都留痕，走势随时可重算。
产出：
- `src/yuqing/issues/store.py`
- `tests/t40_issue_store_test.py`
- 表 `issue_events`、`issue_points`
规则：
1. `issue_events` 是唯一事实源（只追加）。议题的当前状态由事件推导，不另存一份可改的表。
2. `issue_id` 一经分配永不复用；被合并的议题保留编号并指向去向。
3. 两级：主题下面挂议题，不再往深。
4. 人工收口：`yuqing issues export-review` 生成本周待审清单（HTML 供看，另附可编辑的 TOML）；人改完后 `yuqing issues apply-review <文件>` 把操作写成事件。同一文件重复应用不产生重复事件。
5. 每个议题可标相关职能：制作人、策划、美术UI、技术、运营市场、本地化、社区管理、文案编剧。
验收（全部通过才算完成）：
- `pytest -q tests/t40_issue_store_test.py`：合并后旧编号查得到去向，走势合并正确；拆分与改名留痕；重复应用收口文件结果不变
完成后：提交、勾掉清单，接着做本阶段的下一张；阶段做完或遇到闸门再停。
```
